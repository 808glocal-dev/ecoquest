# 뽀송별 v2.0 — GitHub / Vercel 적용 안내

## 바뀐 부분
- 첫 방문 로그인부터 우주 분위기의 뽀송별 화면으로 표시
- 게임 안에서 토끼가 **화면 터치·클릭·방향키/WASD·모바일 조이스틱**으로 실제 이동
- 사진 우체국/꽃길 산책/기록/친구/바람 쉼터: 목적지로 걸어가 도착한 뒤 상호작용
- 사진 우체국에서 참여 중인 챌린지 미션 선택 → 토끼가 카메라로 이동해 누름 → 기존 `window.openAI(m,uid,challengeId)` 호출
- 인증 이후 기존 Gemini/AI 및 `saveMission` 흐름을 그대로 사용
- 별/산책/기록/친구/함께/내방 메뉴와 원래 기능으로 돌아가는 버튼
- 음악은 **사용자가 버튼을 눌러야** 재생되는 자체 생성 잔잔한 신시사이저 음
- 기존 미션 횟수·추정 CO₂·포인트 데이터 표시
- 기존 `bunny_patch.js` 파일과 그 데이터 로직 유지; 화면을 중복 덮는 실험용 `ecoquest_world_patch.js`의 실행만 보류
- 이전 PWA 캐시 버전 변경으로 구버전 HTML이 계속 보이는 현상 완화

## 기존 회원과 기록 보호
- Firebase `projectId=ecoquest-c6380`, 기존 인증 코드, users/missionLogs 컬렉션 이름 그대로 사용
- 새 게임 JS에는 Firebase 쓰기/삭제/리셋 로직 없음
- 사용자가 미션을 인증하면 **기존 AI 인증/저장 코드만** 실행
- 원본 파일 중 수정된 항목은 이 문서 및 아래 ZIP의 항목으로 한정
- 기존 Firebase 규칙과 실제 회원 계정 동작은 운영 환경에서 검증해야 함. 백업과 테스트 배포 필수

## 기존 GitHub 저장소에 적용 (권장)
1. **기존 저장소 백업**: `index.html`을 `index_before_bosong.html`로 복사하고 Git 커밋 유지
2. `pposong_github_update.zip` 압축을 풀고 내부의 **파일과 폴더 자체**를 기존 저장소 최상위에 같은 경로로 올림
3. 기존 파일을 덮어쓰는 것에 동의하고 커밋. ZIP 파일 자체만 업로드하면 적용되지 않음
4. Vercel이 GitHub 배포를 완료하면 강력 새로고침(Ctrl+Shift+R). 설치형 PWA는 캐시/앱 재실행 확인
5. 로그인 → 사진 우체국 누르기 → 캐릭터 도착 → 미션 선택 → 기존 AI 모달 → 실제 기록까지 테스트

## 처음부터 새 GitHub 저장소에 올릴 경우
- `pposong_github_full.zip`을 **압축 해제한 내부 파일/폴더**를 저장소 루트에 업로드
- `ecoquest-main` 폴더를 한 번 더 중첩하여 업로드하지 않기 (index.html이 루트여야 함)
- Vercel 프로젝트와 Firebase 승인 도메인 및 환경변수/API 설정은 기존 설정 유지

## 데모 체험
- `bosong_playable_demo.html`은 단독으로 열어 걷기, 카메라 누르기, 음악, 기록 판넬을 시험할 수 있음
- 데모는 **가짜 미션 데이터**이며 실제 AI 서버나 Firebase에 접근하거나 사진을 업로드하지 않음

## 조작법
- PC: 원하는 장소 클릭 → 자동 이동 / 화면 빈곳 클릭하여 걷기 / 방향키 또는 WASD / 장소 앞 Enter
- 모바일: 장소 탭 → 자동 이동 / 화면 탭 / 왼쪽 조이스틱 / 가까우면 나타나는 '장소 누르기'
- 하단 메뉴: 별, 산책, 기록, 친구, 함께, 내방. 기존 기능은 ☷ 메뉴 / 상세보기로 연결

## 검증 결과 및 한계
- 로컬 브라우저 모의 데이터 환경: 데스크톱 1440x900, 모바일 390x844에서 이동→미션 목록→선택→카메라 누르기→기존 openAI 호환 호출 시험 통과
- 기록 화면 전환, 스크립트 오류(0개) 확인
- 운영 Firebase 실계정 로그인/AI 서버 인증/동시 접속/PWA 업데이트는 별도 검증 전
- 이 버전은 WebGL/Three.js 3D 게임 엔진이 아니라 **3D 캐릭터 이미지와 직접 조작 가능한 2.5D 인터랙티브 월드**임
- 참고해 준 우주둥둥 URL은 현재 환경에서 접속되지 않아, 동일한 엔진·그래픽·조작을 복제했다고 주장하지 않음
- 기존 원본 코드에도 클라이언트 포인트 적립 등 보안 강화 과제가 있으므로 실제 지급/관리자 권한은 서버 검증 필요
