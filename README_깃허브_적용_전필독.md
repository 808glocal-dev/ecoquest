# ☁️ 뽀송별 7개 별 풍경 확장판 — GitHub 적용 설명서

## 무엇이 바뀌었나요?
- **7개 행성별 서로 다른 3D 지형과 소품**: 숲/산호 해변/풍차 언덕/노을 마을/농장/이웃 광장/밤하늘 산책길
- **끊기지 않는 지형 스트리밍**: 48×48 게임 단위 구역을 이동할 때 결정적으로 생성하고, 멀어진 구역의 그래픽 메모리를 해제합니다. 실제 무한대 데이터가 저장되는 것은 아닙니다. 거리가 멀수록 안개로 자연스럽게 연결합니다.
- **행성 접근 → 착륙 → 3D 산책**: 우주와 지상은 구분되며, 클릭/드래그/휠/WASD/앉기 조작 지원
- **원본 미션 40종을 별마다 배치**: 기존 ID 유지, 실제 미션 카메라 표지 근처에 가면 그 미션의 인증 화면 열기
- **기존 회원 데이터 사용**: Firebase 프로젝트/회원 UID/`users`/`missionLogs` 구조 그대로 읽기. 포인트는 **조회만** 합니다.
- **초록지구별**: 기존 미션 완료 횟수가 쌓일수록 색이 더 맑아지는 가상의 연출. CO₂ 숫자는 추정치로 표시
- **친구 공개 opt-in**: Firestore 별도 `pposongPresence` 문서 사용, 게임 좌표만 공유. 별도 보안 규칙이 필요합니다.
- **음악**: 버튼을 누르면 오리지널 잔잔한 신시사이저 음이 시작되며 끌 수 있습니다.

## 압축파일을 GitHub에 넣는 방법
1. 기존 `ecoquest` 저장소 **main 전체를 복제하는 테스트 브랜치**를 먼저 만듭니다. 기존 운영 사이트의 회원 DB는 별도이며, 이 ZIP은 회원 문서를 삭제하거나 초기화하지 않습니다.
2. 압축을 풀고 `game/`, `api/`, `tests/`, `package.json`, `index.html`의 **상대경로를 유지**하여 저장소 최상단에 업로드합니다. 기존 `api/verify-mission.js` 등 다른 기존 파일을 제거하지 않습니다.
3. 운영 `main`이 아닌 **브랜치 Preview Deployment**에서 `/game/`을 엽니다. 기존 UI를 대신하는 `/index.html`도 포함되지만, 운영 반영은 기능 검증 후로 미룹니다.
4. Node.js 20 이상에서 `npm run check`로 기본 게임 데이터/이동/맵 생성 검사를 할 수 있습니다.
5. PC에서 마우스 드래그·휠, 행성 클릭 → 접근 → 착륙, 지상 걷기, 7개 행성 각각의 풍경과 멀리 걸을 때 이어지는 길을 검사합니다. 모바일도 각각 확인합니다.
6. Firebase 인증/서버 API를 별도 테스트 회원으로 검증하고, 연결되지 않은 기존 상점·모임 등은 이전 작업이 끝날 때까지 운영 전환을 보류합니다.

## 중요한 운영 제약
- **이것은 코드 전달용 통합 후보 파일이지 검증 완료된 운영 최종본이 아닙니다.** 이 환경에서는 WebGL을 사용할 수 없어 실제 3D 렌더링의 시각 품질을 확인하지 못했고, 2D 대체 모드에서 이동·맵 갱신만 확인했습니다.
- Vercel 서버에서 `/api/pposong-verify`가 성공하려면 **서버 전용** 환경 변수 `GEMINI_API_KEY`, `FIREBASE_SERVICE_ACCOUNT_JSON`이 있어야 합니다. 서비스 계정 JSON을 GitHub에 넣거나 채팅으로 보내면 안 됩니다. 부재 시 서버는 인증을 **거부**하고 데이터 저장도 하지 않습니다.
- 기존 사이트의 상점 구매·결제·배송·공동 챌린지·관리자 기능과 일부 패치는 아직 게임 내부로 완전히 이전되지 않았습니다. 버튼을 조작해 실제 구매를 수행하지 않도록 상점은 **조회 전용**입니다.
- 포인트 잔액은 그대로 보존하지만, 이 게임의 새 인증 경로에서는 **포인트를 추가 지급하지 않습니다**. 기존 서비스의 포인트 정책을 계속 운영하려면 별도 조정·검증이 필요합니다.
- 보안 위험: 원래 브라우저에서 포인트/CO₂ 갱신이 가능한 코드 경로는 **Firebase 규칙 및 기존 API 수정 없이 자동으로 차단되지 않습니다**. 운영 전환 전에 보안 규칙을 점검해야 합니다.
- 친구 접속은 `FIRESTORE_PRESENCE_RULES_병합용.txt` 내용을 **기존 규칙에 병합**하고, 권한·인덱스·2인 테스트를 수행해야 합니다. 규칙 조각을 전체 규칙 대신 게시하지 마세요. 실제 접속한 친구의 공개 기록만 보여야 합니다.
- PWA/캐시나 Vercel 배포 설정 때문에 파일 업로드 직후 옛 화면이 보일 수 있습니다. Preview 배포가 Ready인지, 실제 `index.html`과 `/game/main.js?v=2`가 내려오는지 확인하세요.

## 실제 운영 홈페이지 교체
압축파일 루트의 `index.html`은 별도 이전 사이트로 돌아가지 않고 **뽀송별 게임을 곧바로 엽니다**. 단, 테스트 브랜치에서 충분히 점검하고 인증·회원·상점·모임·관리 기능 이전과 보안 검증이 끝난 다음에만 운영 `main`으로 병합하세요. 기존 `index.html`은 GitHub 커밋으로 언제든 복구 가능하도록 백업합니다.

## 독립 체험 파일
`뽀송별_7개별_바로체험.html`은 단독 HTML로, 별 7개 선택·착륙·산책·미션 UI만 확인합니다. **실제 회원 로그인이나 저장은 실행되지 않으며** 장치에서 WebGL을 쓸 수 없으면 평면 대체 화면으로 표시됩니다. 전체 프로젝트 설치 없이 우선 조작을 확인할 때만 사용하세요.
