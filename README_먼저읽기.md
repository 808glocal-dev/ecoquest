# 뽀송별 3D 멀티플레이 · 테스트용

## 추가 파일과 변경점
- `index.html`: 기존 ZIP의 로그인, AI 인증, 포인트, 40종 미션, 다른 패치 태그를 유지하고, 마지막에 3D 게임 스크립트만 연결
- `pposong_3d.js`: Three.js 기반 3D 우주, 7개 행성, 착륙 후 3D 지형·캐릭터, 40개 미션 장소, Firebase에 동의한 여행자 표시
- `firestore_presence_rules_SNIPPET.txt`: 새로운 접속 컬렉션용 규칙 **조각**. 운영 규칙 전체를 덮어쓰지 말 것

## 적용
1. **운영 main은 그대로**. GitHub의 `pposong-3d-test` 브랜치를 만들기.
2. `index.html`, `pposong_3d.js` 2개 파일만 저장소 루트에 올리기. `api/`, 다른 `*_patch.js` 전부 보존.
3. 미리보기 배포에서 `?pposongDemo=1`을 붙이면 로그인 전에도 게임의 산책 기능을 시험할 수 있음. AI 인증은 로그인 필요.
4. Firebase 실시간 친구는 Firestore rules에 위 **조각을 안전하게 병합하여 배포한 다음** 두 개의 서로 다른 로그인 계정으로 같은 별에 들어가서 각각 `친구 → 다른 여행자에게 내 캐릭터 보이기`를 켜야 나타남.
5. 서비스 워커가 낡은 스크립트를 캐시할 수 있으므로 먼저 새 창/하드 새로고침에서 테스트. 캐시 정책 변경 전에는 운영에 배포하지 말 것.

## 중요한 제약
- 구형/저사양 스마트폰에서 WebGL이 차단될 수 있음; Three.js CDN 접근 필요.
- 이 버전의 3D 캐릭터는 기하 도형으로 만든 **실제 3D 프로토타입**이지 고품질 리깅/모션캡처 캐릭터는 아님.
- 움직임 동기화는 약 12초 간격. 즉각적인 애니메이션 동기화나 채팅/초대/친구 맺기는 구현 전.
- 실시간 기록 공개는 개별 회원이 설정한 경우만 보여 주고, 그 숫자는 **클라이언트가 제출한 값**이므로 공식 실적이나 검증된 인증 통계로 취급하면 안 됨. 서버 검증 필요.
- 종료/로그아웃 시 문서 삭제를 시도하고 45초 지난 문서는 화면에서 숨기지만, 네트워크 단절 때 Firestore 문서 자체가 남을 수 있음. 운영 시 Cloud Functions TTL 청소를 권장.
- 실제 운영 AI 인증은 기존 `openAI` 함수를 호출. Firebase 보안·중복 인증·포인트 지급 규칙을 이 코드가 수정하거나 검증한 것은 아님.
- 기존 회원 DB의 users/missionLogs를 이 게임이 업데이트/삭제하지 않음.
