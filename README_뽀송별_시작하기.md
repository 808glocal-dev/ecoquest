# ☁️ 뽀송별: 기존 에코퀘스트를 게임으로 재구축하는 첫 번째 독립 프로젝트

## 가장 먼저 알아둘 점
이것은 `index.html` 끝에 붙이는 패치가 **아니에요**. 기존 회원 데이터베이스는 그대로 연결하고, 게임을 새로운 `/game/` 경로에서 테스트하는 **독립 프로젝트**입니다. 최종 목표는 테스트 후 `/`(메인 홈페이지)도 오직 뽀송별 게임으로 여는 것입니다.

**현재 운영 중인 `main` 또는 기존 `index.html`, `service-worker.js`, `api/`, `assets/`, `icons/`를 삭제하거나 덮어쓰지 마세요.**

## 깃허브 업로드 방법
1. GitHub `808glocal-dev / ecoquest`에서 `main ▼` → `pposong-rebuild-test` 새 브랜치를 만들어 이동합니다.
2. 배포용 ZIP 압축을 풉니다. ZIP에는 **`game/` 폴더**, **`api/` 폴더** 안의 새 파일 2개, `package.json`, 설명서가 들어 있어요.
3. 원본 파일을 하나도 지우지 말고 **새 게임 파일만 같은 폴더 구조로 추가**합니다. 기존 `api/verify-mission.js`는 수정하지 않습니다.
4. Vercel에서 이 브랜치의 Preview Deployment가 준비되면 `https://<미리보기-주소>/game/`을 엽니다. 기존 메인 주소는 당분간 변경되지 않습니다.
5. 첫 체험은 로그인하지 않아도 가능해요. 게임 안에서 우주 → 행성 클릭 → 착륙 → WASD 또는 바닥 클릭 이동 → 미션 목록을 테스트합니다.
6. 실제 기존 회원 로그인, 기록 조회, 인증 저장은 **운영 서버 설정과 보안 규칙을 확인한 뒤 별도 테스트 계정**으로만 검증합니다.

## 현재 개발된 것 (첫 기능 단위)
- 외부 게임 엔진 CDN 없이 구동되는 자체 WebGL 3D 세계. 일부 브라우저는 WebGL이 차단되어 **간소화된 2D 대체 화면**으로 표시됩니다.
- 우주 7개 행성 탐색, 마우스/휠/터치, 착륙, 걷기, 앉기, 카메라 시점 조작
- 원본 `MISSIONS` 40개의 **ID·이름·CO₂ 참고 수치 보존**. 행성별 미션 장소와 미션 메뉴 연결
- Firebase 기존 프로젝트 `ecoquest-c6380` 계정 및 `users/{uid}` 읽기 (기존 회원 문서 신규 생성/초기화 안 함)
- 로그인 상태에서 `missionLogs`의 본인 기록, 기존 `users.point`, `missionCount`, `co2` 표시
- 사진 AI 검증 후 서버에서 중복 인증을 검사하고 `users`·`missionLogs`·`verifications`를 갱신하는 **별도 보안 API 코드**
- 친구 공개는 opt-in으로만, 같은 별에서 공개를 켠 회원의 간단한 캐릭터/목록 표시 기능 코드
- 잔잔한 **오리지널 신시사이저 음향** 수동 재생/중지

## 아직 이전되지 않은 기존 기능
이 단계에서 **상점 구매·결제·배송, 기존 챌린지 가입/탈퇴·반복 일정·공동 모임, 피드 댓글, 관리자 대시보드, 모든 기존 보조 패치 동작**은 새 게임 안에서 미완성입니다. 특히 **구매/결제를 임의로 재구현하면 기존 회원 포인트가 잘못 차감될 수 있으므로 버튼을 막아 둔 상태**입니다. 실제 친구 동기화도 Firebase 규칙·인덱스를 배포하고 두 회원으로 시험하기 전에는 검증 완료가 아닙니다.

## AI 인증 서버를 실제로 연결하려면 (중요)
- 원본의 `GEMINI_API_KEY`를 Vercel 환경 변수에서 계속 사용합니다.
- **추가 서버 전용 환경 변수:** `FIREBASE_SERVICE_ACCOUNT_JSON`. Firebase 콘솔에서 받은 서비스 계정 JSON을 Vercel의 서버 환경 변수에만 등록해야 합니다. **채팅이나 GitHub 코드에 비밀키 JSON을 올리지 마세요.**
- 이 설정이 없으면 `POST /api/pposong-verify`는 **503(안전한 실패)**를 돌려줍니다. 그 경우에는 미션/포인트가 변경되지 않습니다.
- `package.json`의 `firebase-admin` 의존성을 Vercel이 설치해야 합니다.
- 기존 미션과 동일한 ID를 사용하고, 서버가 인증 성공을 확인할 때만 `users/{uid}`에 기록합니다. **기존 point 잔액은 보존하지만 새 게임은 추가 포인트를 지급하지 않습니다.** 이는 '힐링이 보상'이라는 기획을 반영한 것입니다.
- `users/{uid}/dailyClaims/{YYYY-MM-DD_mN}`로 당일 동일 미션 중복 인증을 막습니다. 하루 AI 시도 12회 제한을 둡니다. 기존 사이트에서 쓰던 다른 인증 경로까지 서버에서 모두 차단하는 것은 **기존 Firebase 보안 규칙 검토 이후** 가능합니다.
- 화면에 표시되는 CO₂는 기존 서비스의 추정 계수를 가져온 것입니다. 실제 탄소 배출 감소를 직접 측정하거나 정부 인증을 받았다고 주장하면 안 됩니다.

## 친구 공개: 필요한 Firebase 규칙 / 인덱스
`FIRESTORE_PRESENCE_RULES_병합용.txt` 파일은 **전체 규칙이 아니라 규칙의 일부**입니다. 운영 규칙 전체를 통째로 덮어쓰지 마세요. 사용자가 공개를 켜야 `pposongPresence/{uid}`에 자신의 **게임 속 좌표**와 공개 닉네임만 저장해요. 공개 끄기·우주 복귀·로그아웃 시 문서 삭제를 시도합니다. 일시적인 연결 끊김 시 문서는 남을 수 있어도 55초 이상 갱신되지 않은 이용자는 화면에 표시하지 않습니다.

복합 쿼리 인덱스 `(visible ASC, planet ASC)`가 필요할 수 있습니다. 실제 실시간 동기화와 개인정보 보호는 Firebase 규칙 검토 후에 활성화하세요.

## 게임 화면을 서비스 메인으로 전환하는 마지막 단계 (아직 하지 마세요)
- 상점/결제·챌린지 가입·관리자 등 기존 기능 이전 완료
- 실제 로그인·AI 인증 성공과 중복 인증·데이터 보존·모바일 WebGL 테스트 완료
- Firebase 규칙과 서버 환경 변수 점검, 이전 버전으로 복귀 가능한 커밋 확보
- **그 뒤에만** 메인 `index.html`을 `/game/`으로 이동시키는 전환을 배포. 이때 방문자는 기존 카드형 홈페이지가 아닌 게임만 보게 됩니다.

## 데이터 보존
앱 설치/새 UI만으로 기존 회원 데이터가 이동·삭제되지는 않습니다. 기존 Firebase 프로젝트·회원 UID·문서 컬렉션을 재사용합니다. 이번 ZIP의 게임 파일은 회원 컬렉션 전체를 삭제하거나 다시 만드는 코드를 포함하지 않습니다. 단, 서버 기능과 규칙을 실제로 적용하기 전에는 **운영 데이터 보존을 완전히 검증했다고 주장할 수 없습니다**. 먼저 Firebase 백업과 테스트 계정으로 점검하는 것이 안전합니다.
